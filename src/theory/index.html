01 What is Emmet?

Answer

Emmet is a shorthand built into editors such as VS Code. You type a small abbreviation, press Tab, and it expands into full HTML or CSS. It does not run in the browser. It only helps you write markup faster.

Example

Type this and press Tab:

div.card>h1#title+p*2

VS Code expands it to:

<div class="card">
  <h1 id="title"></h1>
  <p></p>
  <p></p>
</div>

In an interview: “Emmet is an editor toolkit for expanding abbreviations into HTML and CSS. . means class, # means id, > means child, + means sibling, and *n repeats an element.”

02 Difference between a library and a framework?

Answer

A library is a set of functions you call when you need them. You stay in control of the app. A framework is the structure of the app. You plug your code into its rules, and it calls your code. That difference is called inversion of control.

LibraryFramework
You call itIt calls you
Solves one jobDecides architecture, routing, and flow
React is a UI libraryAngular is a framework

Example

With React you decide the files, the router, and when to render. React only gives you createElement, components, and state. With Angular, the framework already owns modules, dependency injection, routing, and the bootstrap process. Your code fits into that.

In an interview: “React is a library because it only renders UI. I choose everything else. A framework owns the application lifecycle and calls my code.”

03 What is a CDN? Why do we use it?

Answer

A CDN, Content Delivery Network, is a group of servers spread across the world that store copies of the same files. The browser downloads the file from a server close to the user, so it arrives faster.

We use a CDN when learning React so we can add React with a script tag and skip Node, npm, and a bundler. The browser may also cache that file, so the next page loads faster. Our own server does not have to send React’s code.

Example

<script crossorigin src="https://unpkg.com/react@18/umd/react.development.js"></script>
<script crossorigin src="https://unpkg.com/react-dom@18/umd/react-dom.development.js"></script>

unpkg.com is a CDN for npm packages. In a real product we usually install React and bundle it ourselves, because we want a locked version, smaller files, and no dependency on a third-party URL at runtime.

04 Why is React known as React?

Answer

React is named for how the UI behaves. The screen reacts when data changes. You describe the UI for the current state. When state changes, React updates the parts of the screen that need to change.

Jordan Walke built it at Facebook. The idea is: UI is a function of state. UI = f(state). You do not manually find a paragraph and rewrite its text after every change. You change the data, and the view reacts.

Example

const heading = React.createElement(
  "h1",
  { id: "title" },
  "Hello from React"
);

const root = ReactDOM.createRoot(document.getElementById("root"));
root.render(heading);

That h1 is the view for this data. If the text later comes from a variable and that variable changes, React renders again. That reaction is the name.

05 What is crossorigin in a script tag?

Answer

crossorigin tells the browser how to request a file from another domain. React’s CDN scripts live on unpkg.com, which is a different origin from your page. crossorigin (or crossorigin="anonymous") makes that request a CORS request without sending cookies or other credentials.

We add it for two practical reasons:

  • If the script throws, the browser can show the real error. Without CORS, a cross-origin script error is hidden as just “Script error.”
  • If you also use Subresource Integrity (integrity="sha..."), the browser requires crossorigin. Otherwise it will not verify the file.

Example

<script
  crossorigin
  src="https://unpkg.com/react@18/umd/react.development.js">
</script>

anonymous means “fetch it, but do not send my login cookies.” use-credentials would send cookies. For public CDN files we want anonymous.

06 What is the difference between React and ReactDOM?

Answer

React is the core library. It knows elements, components, and (later) hooks and state. It does not know what a browser div is.

ReactDOM is the renderer for the browser. It takes the elements React created and puts them into the real DOM. ReactDOM.createRoot and root.render live here.

ReactReactDOM
React.createElementReactDOM.createRoot
Describes the UI treePaints that tree into the page
Same core for web and nativeWeb only. React Native has its own renderer

Example

// React: describe a node. Nothing is on the page yet.
const heading = React.createElement("h1", {}, "Hello World");

// ReactDOM: find the empty div and put the node on the page.
const root = ReactDOM.createRoot(document.getElementById("root"));
root.render(heading);

In an interview: “They are split so React’s model can render to different targets. The web uses ReactDOM. Mobile uses React Native.”

07 react.development.js vs react.production.js

Answer

Both files are React. The development file helps you learn and debug. The production file is the one you ship to users.

development.jsproduction.js
SizeLargerMinified, smaller
WarningsClear errors and extra checksWarnings removed
SpeedSlowerFaster
Use it forLocal learningReal users

Example

<!-- while learning -->
<script crossorigin src="https://unpkg.com/react@18/umd/react.development.js"></script>

<!-- on a live site -->
<script crossorigin src="https://unpkg.com/react@18/umd/react.production.min.js"></script>

If you pass the wrong type of child or forget a key in a list, the development build prints a useful message in the console. The production build stays quiet and weighs less, because users should not download developer warnings.

08 What is async and defer?

Answer

Both attributes go on a classic script tag. They tell the browser to download the JavaScript without stopping HTML parsing. They differ in when the script runs.

No attributeasyncdefer
HTML parsingPauses while the script downloads and runsContinuesContinues
RunsImmediately, before the rest of the HTMLAs soon as this file finishes downloadingAfter the HTML is parsed
OrderDocument orderWhichever file arrives firstDocument order
Good forTiny scripts that must run nowIndependent files, such as analyticsApp scripts that need the DOM

Example

<script src="analytics.js" async></script>
<script src="app.js" defer></script>

analytics.js can run the moment it arrives. It does not care about your div. app.js waits until the HTML is ready, so document.getElementById("root") exists, and it still runs before DOMContentLoaded.

For the React CDN scripts in this repo, leave both attributes off and put the scripts before your own code. React must finish loading before the next script calls React.createElement. async could run your code before React arrives.

Episode 2 — npm, bundlers, and the project files

09 What is NPM?

Answer

NPM is two things people mix up. The npm registry is the public store of JavaScript packages. The npm CLI is the program that installs those packages, runs scripts, and writes package.json.

It is not a compiler and not a bundler. It only fetches code and records versions. Yarn and pnpm talk to the same registry with a different client.

Example

npm init -y
npm install react react-dom
npm install -D parcel

In an interview: “npm is the package manager. I use it to install libraries and to run the scripts listed in package.json.”

10 What is Parcel / Webpack? Why do we need it?

Answer

Parcel and Webpack are bundlers. The browser cannot natively understand a whole app of imports, JSX, images, and CSS the way we write them in development. A bundler walks the dependency graph from an entry file, transforms each file, and emits a small set of files the browser can load.

We need one because:

  • JSX and modern syntax must become plain JavaScript.
  • Many modules become fewer HTTP requests (or smartly split chunks).
  • Development gets a local server, refresh, and error overlay.
  • Production gets minify, tree shaking, and hashed filenames for cache.

Webpack is configured in detail. Parcel aims for zero config: you point it at index.html and it finds the rest. Vite is another option: it serves source files with native ESM in dev and bundles for production with Rollup.

In an interview: “A bundler turns my source tree into something a browser can ship. I need it the moment I leave CDN script tags and start using modules and JSX.”

11 What is .parcel-cache?

Answer

It is Parcel’s local cache. After the first build, Parcel stores transformed files so the next build only redoes what changed. That is why the second npx parcel index.html is much faster.

It is machine-specific, huge, and disposable. If a build looks cursed, delete .parcel-cache and dist and build again. Put it in .gitignore.

12 What is npx?

Answer

npx runs a package’s binary without you thinking about the path. It prefers ./node_modules/.bin. If the package is not installed, it can download it for that one run.

npm installs and manages packages. npx executes them.

Example

npx parcel index.html
npx create-react-app my-app

In an interview: “npx parcel runs the Parcel CLI from this project’s node_modules. I do not need a global install.”

13 dependencies vs devDependencies

Answer

dependencies are code the app needs when it runs for a user: React, ReactDOM, a router. devDependencies are tools you only need while developing or building: Parcel, ESLint, Jest, TypeScript.

dependenciesdevDependencies
Installnpm i reactnpm i -D parcel
Ships to users?Yes, in the bundleNo, only on your machine / CI
Production installKeptSkipped with npm i --omit=dev

For a frontend app that you bundle, Parcel still goes in devDependencies because users download the dist files, not Parcel itself. React stays in dependencies because it is in that bundle.

14 What is Tree Shaking?

Answer

Tree shaking is dead-code elimination. The bundler looks at static import / export (ESM), sees which exports you never use, and leaves them out of the production bundle.

It works when the module has no surprise side effects. CommonJS require is harder to shake because it is dynamic. Mark packages with sideEffects: false in package.json when that is true, so Webpack/Parcel/Rollup can drop unused files.

Example

// utils.js
export function add(a, b) { return a + b; }
export function unused() { return 42; }

// app.js
import { add } from "./utils.js";
add(1, 2);
// production bundle can omit unused()

In an interview: “Tree shaking drops unused ESM exports so the user does not download code we never call.”

15 What is Hot Module Replacement?

Answer

HMR updates a module in the running page without a full reload. You keep component state, the URL, and the console. Parcel and Webpack (and Vite) push the changed file over a websocket and swap it in.

A full refresh rebuilds everything and wipes state. HMR is a development feature. Production builds do not use it.

In an interview: “HMR patches the module I edited so I do not lose the form I was filling in.”

16 Five Parcel superpowers — describe three

Answer

Favourites to name:

  1. Zero config — point at HTML and go
  2. Hot Module Replacement
  3. Built-in tree shaking and minification in production
  4. File watcher and caching (.parcel-cache)
  5. Out-of-the-box support for JSX, CSS, images, and HTTPS in the dev server

In my own words

Zero config. I do not write a 200-line webpack file to start. Parcel reads index.html, follows script and link tags, and figures out loaders itself. That is why Namaste React uses it to get a project running in minutes.

HMR. I save App.js and the browser updates that module. I am not waiting for a full page reload and I do not lose in-memory state.

Production build. parcel build minifies, tree-shakes, hashes filenames, and writes a dist folder I can deploy. The same tool that served me in development ships the app.

17 What is .gitignore? What goes in it?

Answer

.gitignore is a list of paths Git should not track. If a file is already committed, adding it here does not untrack it — you still have to git rm --cached.

Add: node_modules/, dist/, .parcel-cache/, .env and other secrets, OS junk (.DS_Store), editor folders if you want, coverage and log files.

Do not add: source code, package.json, package-lock.json, .gitignore itself, README, public assets you actually need, and config the team shares (.eslintrc, tsconfig.json).

dist/
.parcel-cache/

18 package.json vs package-lock.json

Answer

package.json is the manifest you write: name, scripts, and version ranges (^18.2.0). package-lock.json is the exact tree npm resolved: every package, nested dependency, and integrity hash.

package.jsonpackage-lock.json
Who writes itYounpm, on install
VersionsRangesExact pins
Commit it?YesYes

Two machines with the same lock file get the same node_modules. Without the lock file, ^ can pull a newer patch next month and break the build.

19 Why should I not modify package-lock.json?

Answer

It is generated. Hand-edits go stale the next npm install, and you can break integrity hashes so npm refuses to install. Change versions in package.json (or run npm update / npm i pkg@x) and let npm rewrite the lock file. Then commit that generated result.

20 What is node_modules? Should I push it to Git?

Answer

node_modules is the folder of every installed package and their dependencies. It is large, platform-specific in places, and fully rebuildable from the lock file with npm install.

Do not commit it. The repo stays small, clones stay fast, and everyone installs the same tree from package-lock.json. CI does the same.

21 What is the dist folder?

Answer

dist (distribution) is the bundler’s output: minified JS, hashed CSS, processed HTML. That is what you deploy to Netlify or S3. It is not source. Delete it anytime; Parcel will recreate it. Ignore it in Git so you do not commit generated assets.

22 What is Browserslist?

Answer

Browserslist is a shared query that tells tools which browsers you support. Babel, Autoprefixer, and Parcel read it so they transpile and prefix only what those browsers need.

You put it in package.json as browserslist (that is the real name) or in a .browserslistrc file.

"browserslist": [
  "last 2 Chrome versions",
  "not dead"
]

In an interview: “Browserslist is the target list. The bundler uses it so I do not ship IE11 polyfills if I do not support IE11.”

24 Caret ^ vs tilde ~ in versions

Answer

Semver is MAJOR.MINOR.PATCH. A range in package.json tells npm what it is allowed to install.

  • ^18.2.0 (caret) — any compatible version that does not bump the left-most non-zero number. For 18.2.0 that means >=18.2.0 <19.0.0. New minors and patches are OK.
  • ~18.2.0 (tilde) — only patches: >=18.2.0 <18.3.0.
  • No prefix, 18.2.0 — that exact version.

The lock file still pins the exact install. Caret/tilde only matter when the lock is missing or you run an update. Prefer committing the lock file so CI is exact.

25 Script types in HTML

Answer

A <script> tag’s type tells the browser how to treat the text. From MDN:

typeMeaning
omitted or text/javascriptClassic script. Runs as a blocking script unless async / defer.
moduleES module. Deferred by default, can import, has its own scope, strict mode.
importmapJSON that maps bare specifiers (react) to URLs.
speculationrulesJSON for prefetch/prerender hints. Not executable JS.
any other MIME, e.g. application/ld+json or a made-up typeThe browser does not execute it. Useful as a data block.
 
<script src="app.js"></script>
<script type="module" src="main.js"></script>
<script type="importmap">
{ "imports": { "react": "https://esm.sh/react" } }
</script>

async and defer apply to classic scripts. Module scripts already wait for HTML parse (like defer) and still run in order among themselves. nomodule is a fallback for old browsers that do not understand modules.
