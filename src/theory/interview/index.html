JavaScript

01 Execution context

Answer

An execution context is the environment where a piece of JS runs. It has a variable environment (bindings), a lexical environment (scope chain), and a this binding. There is a global context, one function context per call, and eval (avoid it).

Creation phase: hoist var / function declarations, set this. Execution phase: assign values, run statements. Modules get their own module context.

Say

“JS never just runs a line in a vacuum. It creates a context, wires scope and this, then executes.”

02 Call stack

Answer

The call stack is a LIFO structure of active execution contexts. A function call pushes a frame; return pops it. Recursion without a base case overflows the stack. Async work does not sit on the stack waiting — it is scheduled, then a new frame is pushed later.

function a() { b(); }
function b() { console.log("b"); }
a(); // stack: global → a → b → pop b → pop a
03 Closures

Answer

A closure is a function plus the lexical environment it was created in. The inner function can read and write outer variables even after the outer function has returned. Used for data hiding, factory functions, and hooks.

function makeCounter() {
  let n = 0;
  return () => ++n;
}
const c = makeCounter();
c(); // 1 — n is still alive

Stale closures happen when a callback captured an old value (classic useEffect / setTimeout bug).

04 Hoisting

Answer

During context creation, declarations are registered before the body runs. function declarations are fully hoisted. var is hoisted and initialized as undefined. let / const are hoisted but stay in the Temporal Dead Zone until the line runs. class is also TDZ.

console.log(a); // undefined
var a = 1;
console.log(b); // ReferenceError
let b = 2;
05 Scope

Answer

Scope is where a binding is visible. JS has global, function, block (let/const/class), and module scope. Lexical scope is decided by where the function is written, not where it is called. The scope chain walks outward until global.

06 this

Answer

this is set at call time for regular functions: method call → object, bare call → undefined in strict / global in sloppy, new → new instance, call/apply/bind → explicit. Arrow functions have no own this; they inherit from the enclosing lexical scope. Event handlers bind this to the element unless you use an arrow or bind.

07 Promises

Answer

A Promise is an object for a future value: pending, fulfilled, or rejected — one transition, then settled. then / catch / finally return new promises, so you chain. Always return or throw inside then so errors propagate. Unhandled rejections are bugs.

fetch("/api")
  .then((r) => r.json())
  .then(console.log)
  .catch(console.error);
08 async / await

Answer

async functions always return a Promise. await pauses that function until the promise settles, then unwraps the value or throws. Wrap await in try/catch. Do not await independent work in series — start them together and await Promise.all.

09 Event loop

Answer

JS is single-threaded. The event loop: run the call stack to empty, then drain the microtask queue (promises, queueMicrotask, MutationObserver) until empty, then take one macrotask (timer, I/O, UI event), then maybe render. Microtasks can starve rendering if you keep enqueueing them.

10 Map / Set

Answer

Map is a keyed collection that keeps insertion order and allows any key type (objects, NaN). Set stores unique values. Prefer them over objects/arrays when keys are not strings or you need reliable size and iteration. For caches of objects that should not pin memory, use WeakMap/WeakSet.

11 Prototype and OOP basics

Answer

Every object has an internal [[Prototype]] (via __proto__ / Object.getPrototypeOf). Property lookup walks the chain. Constructor functions set Fn.prototype as the prototype of instances. Methods live on the prototype so they are shared. Object.create(proto) builds an object with that proto. Classes are syntax over this model.

12 Classes

Answer

class is not hoisted like a function (TDZ). Methods are non-enumerable on the prototype. extends + super wire the prototype chain. Fields and private #x are instance state. Prefer composition when inheritance trees get deep.

13 Modules (and ESM vs CJS)

Answer

Modules isolate scope, load once (singleton), and declare dependencies. ESM (import/export) is static, tree-shakeable, async in browsers, live bindings. CommonJS (require/module.exports) is sync, Node-legacy, copy of exports at require time. In browsers you need type="module". Mixing them needs interop (default vs module.exports).

14 Deep vs shallow copy

Answer

Shallow copy ({...obj}, Object.assign, [...arr]) copies one level; nested objects stay shared. Deep copy clones the graph. structuredClone handles most cases (not functions, DOM nodes, or prototypes). JSON parse/stringify drops functions, undefined, Dates become strings. React state updates must not mutate nested objects — clone the path you change.

15 Currying

Answer

Currying turns f(a, b, c) into f(a)(b)(c). Useful for partial application and reusable configured functions (event handlers, Redux action creators). Not the same as just passing a callback — it is a transform of arity.

const add = (a) => (b) => a + b;
const add10 = add(10);
add10(5); // 15
16 Memoization

Answer

Cache a function’s result keyed by arguments. Good for pure, expensive, same-input work. Bad if arguments are new objects every call (cache miss) or the function is cheap. In React, useMemo / useCallback / React.memo are memoization of values, functions, and components.

18 Regular vs arrow functions

Regular: own this, arguments, can be constructors, methods on prototypes. Arrow: lexical this, no arguments, not constructable, cannot be generators. Use arrows for callbacks that should keep outer this. Do not put arrows on a class prototype if you need a method that uses instance this from a caller — use a class field arrow if you need auto-bound handlers.

19 call / apply / bind

fn.call(thisArg, a, b) invokes now with arguments listed. fn.apply(thisArg, [a, b]) same with an array. fn.bind(thisArg, a) returns a new function with locked this (and optional partial args). After bind, you cannot re-bind this.

20 IIFE

Immediately Invoked Function Expression: (function () { ... })(). Creates a private scope. Historically used to avoid leaking var into global. Modules replaced most IIFE use. Still seen in bookmarks, isolated snippets, and some library umd wrappers.

21 Callbacks

A callback is a function passed to be called later. Error-first Node style: (err, data). Nested callbacks become “callback hell.” Promises and async/await flatten that. Still used everywhere: array methods, event listeners, setTimeout.

22 Microtasks vs macrotasks

Microtasks: Promise reactions, queueMicrotask, MutationObserver. Run after the current stack, before the next macrotask and before paint if the stack is empty. Macrotasks: setTimeout, setInterval, setImmediate (Node), I/O, UI events, requestAnimationFrame is its own render-aligned queue. Promise.then always beats a setTimeout(0).

23 Promise.all, race, allSettled, error patterns
  • Promise.all — fail fast; one reject rejects the whole thing.
  • Promise.allSettled — wait for all; inspect status / value / reason.
  • Promise.race — first settle wins (good for timeouts).
  • Promise.any — first fulfill; all reject → AggregateError.

Pattern: wrap each promise if you want all-or-log. Use AbortController with fetch. Never swallow errors in empty catch.

24 Destructuring, spread/rest, optional chaining, nullish, map/filter/reduce 
const { a, b: renamed, ...rest } = obj;
const copy = { ...obj, a: 2 };
const first = arr?.[0]?.id ?? "fallback";
arr.map(x => x * 2).filter(x => x > 2).reduce((s, x) => s + x, 0);

Optional chaining short-circuits to undefined. Nullish (??) only replaces null/undefined, unlike || which also replaces 0 and "". Coercion: == coerces, === does not; + with a string concatenates. Prefer explicit Number / Boolean.

25 Object.freeze

Makes an object shallow-immutable: no add/remove/reassign of own properties. Nested objects are still mutable. Object.isFrozen checks. Not a security boundary — just a contract. For deep freeze, recurse (or use Immer + freeze in Redux).

26 Coding: debounce, throttle, deepClone, flatten

Debounce: wait until calls stop for N ms, then run (search input). Throttle: run at most once per N ms (scroll). Deep clone: structuredClone or recursive copy. Flatten: arr.flat(Infinity) or recurse concat.

function debounce(fn, ms) {
  let t;
  return (...args) => {
    clearTimeout(t);
    t = setTimeout(() => fn(...args), ms);
  };
}
function throttle(fn, ms) {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= ms) { last = now; fn(...args); }
  };
}
function flatten(arr) {
  return arr.reduce((acc, x) => acc.concat(Array.isArray(x) ? flatten(x) : x), []);
}
27 Event bubbling and event listeners

Capture (root → target) then bubble (target → root). addEventListener(type, fn, { capture, once, passive, signal }). stopPropagation stops travel; preventDefault stops default action. Remove listeners on unmount or use AbortController signal. Delegation: listen on a parent, use event.target.

28 Higher-order functions

A HOF takes a function and/or returns a function: map, filter, debounce, Redux connect, React HOCs. Interview: “I treat functions as values so I can compose behavior without copy-paste.”

29 Browser APIs: localStorage, sessionStorage, setTimeout, window

localStorage persists per origin until cleared (~5MB, sync, strings only). sessionStorage dies with the tab. Both are XSS-readable — do not store tokens if XSS is possible. setTimeout is a macrotask, delay is minimum not exact, background tabs are clamped. window is the global object in browsers: location, history, fetch, document.

30 Security: XSS, CSRF, SOP, CSP, encryption vs hashing
  • XSS: attacker script in your page. Prevent: encode output, CSP, no dangerouslySetInnerHTML with user HTML, HttpOnly cookies.
  • CSRF: browser sends cookies to your API from another site. Prevent: SameSite cookies, CSRF tokens, no cookie auth on mutating GET.
  • Same-Origin Policy: scheme + host + port must match for JS to read the response / DOM.
  • CSP (Content-Security-Policy): header that allowlists script/style sources. Not “content origin policy.”
  • Encryption: reversible with a key (TLS, AES). Hashing: one-way (password + salt, SHA-256). Use bcrypt/argon2 for passwords, not raw SHA.
31 Garbage collection and memory leaks

JS uses reachability (mark-and-sweep). If something is reachable from roots (stack, globals, DOM, closures), it stays. Leaks: forgotten listeners/timers, detached DOM still referenced, unbounded caches, closures holding large objects, growing arrays in module scope. Fix: remove listeners, clearTimeout, WeakMap for object keys, abort fetches on unmount.

32 WeakMap / WeakSet

Keys (WeakMap) / values (WeakSet) must be objects (or symbols in newer WeakMap). They are weakly held — if nothing else references the object, GC can collect it and the entry vanishes. Not iterable, no size. Use for private data on objects, DOM node metadata, caches.

33 Symbols

Unique immutable primitive. Symbol("desc") never equals another. Used as collision-free object keys and well-known symbols (Symbol.iterator, Symbol.toStringTag). Symbol.for is a global registry. Hidden from typical for...in / Object.keys.

34 Iterators and generators

An iterator is { next() { return { value, done } } }. Iterable objects have [Symbol.iterator]. for...of, spread, and destructure use that. A generator (function*) pauses with yield and produces an iterator. Useful for lazy sequences and custom iterables. Async generators use for await.

35 Event delegation

Attach one listener to a parent. On bubble, check event.target / closest. Works for items added later. Cheaper than N listeners. In React, the root already delegates most events — still useful for vanilla lists or native wrappers.

36 AbortController

const ac = new AbortController(). Pass ac.signal to fetch and addEventListener. ac.abort() cancels in-flight work and removes those listeners. Essential to avoid setState-after-unmount and to cancel stale searches.

37 Fetch lifecycle

Create request → CORS / SOP checks → network → response headers (you can read status before body) → consume body (json() / text() once). Redirects follow by default. Abort via signal. ok is 200–299; 404 still “succeeds” the promise — check response.ok. Then parse. Errors: network reject, HTTP you handle, JSON parse throws.

38 Regex

Know test, exec, String.match/replace/split, flags g i m s u y. ^ $ . * + ? [] () \d \w \s. LastIndex on global regex is a footgun. Prefer well-tested patterns for email/URL; do not invent crypto-grade validation with regex.

React

01 Virtual DOM

A JS tree of React elements that describes the UI. React diffs the next tree with the previous (reconciliation) and applies a minimal DOM update. The win is predictable updates and batching, not “virtual is always faster than DOM.”

02 Basic components

Function components receive props and return elements. Class components exist but new code uses functions + hooks. Components must be pure in render: same props/state → same output, no side effects in the function body.

03 Fiber

Fiber is React’s reconciler unit of work (a fiber node per component). It lets React pause, resume, reuse, and abort work. That enables concurrent features: time-slicing, interrupting a render for a more urgent update, Suspense.

04 Reconciliation and keys

React compares type + key at the same position. Same type → update props. Different type → unmount/remount. Keys tell React which child is which across renders. Unstable keys (index when list reorders) remount or mix state. Keys must be stable and unique among siblings.

05 Hooks overview

Hooks let function components hold state and lifecycle. Rules: only at top level, only in React functions. Order is how React matches hook state. Custom hooks are functions named useX that compose other hooks.

06 Custom hooks

Extract reusable stateful logic (not UI). Share one implementation of fetch, form, or media-query. Each caller gets its own state. Return a small API: values + functions.

07 Context API

Avoid prop drilling for rarely changing, widely needed data (theme, locale, auth). createContext + Provider + useContext. Any consumer re-renders when the provided value identity changes — split contexts or memoize the value. Not a replacement for all state (server cache, frequent updates).

08 React.memo, useMemo, useCallback

React.memo skips a component re-render if props are shallow-equal. useMemo caches a computed value. useCallback caches a function identity so memo children and effect deps stay stable. Measure first; they add complexity and can be slower if overused.

09 Portals

createPortal(node, domNode) renders children into a DOM node outside the parent (modals, toasts). Events still bubble through the React tree, not the DOM parent.

10 Error boundaries

Class components with getDerivedStateFromError / componentDidCatch catch render errors in the subtree and show fallback UI. They do not catch event handlers, async, or the boundary itself. In React 19 you may also see newer APIs — still know class boundaries.

11 Suspense and lazy loading

React.lazy + Suspense code-split a component. Suspense shows fallback while a child is waiting (lazy import, and in modern React, some data frameworks). lazy must default-export a component.

12 Navigation

React Router (or framework routers): routes as a tree, loaders, nested layouts, Link vs a (client vs full reload). Know useNavigate, params, search params, and that navigation is just mapping URL → component tree.

13 useState object/array updates

State is replaced, not mutated. Spread the object/array and change the copy. Nested updates need nested copies (or Immer). Functional updates setX(prev => ...) when next state depends on previous.

setUser((u) => ({ ...u, name: "Ada" }));
setItems((xs) => xs.map((x) => x.id === id ? { ...x, done: true } : x));
14 useEffect: deps, cleanup, stale closure

Effects run after paint. Deps: empty = mount/unmount, omitted = every render (usually wrong), listed = when those values change. Cleanup runs before the next effect and on unmount. Stale closure: the effect captured old state because it was missing from deps. Race: an older fetch finishes last — abort or ignore with a flag.

15 useRef

A mutable box that persists across renders and does not trigger re-render. DOM nodes, timer ids, previous values, “latest callback” refs to avoid stale closures without re-subscribing.

16 useReducer

For complex state transitions: (state, action) => next. Predictable, easy to test, good when next state depends on many fields. Same immutability rules as Redux.

17 Component patterns
  • Controlled vs uncontrolled: value in React state vs DOM owns it (defaultValue + ref).
  • Composition: children / slots instead of boolean prop soup.
  • Render props: children(data) or render={} to share logic.
  • HOC: withX(Comp) wraps; prefer hooks today.
  • Lifting state: move state to the nearest common parent.
  • Compound components: Select + Select.Option sharing implicit context.
18 Pagination

Offset/limit or cursor. UI: page buttons or infinite scroll. Keep page in the URL. Cancel in-flight page requests. Cache pages (RTK Query). Do not splice keys so list state survives page change.

19 Rendering lifecycle, concurrent rendering, batching

Function body = render (pure). Then React commits to DOM, then runs layout effects, then paint, then passive effects. Concurrent: React may start a render and throw it away. Batching: multiple setState in the same event (and in React 18, in timeouts/promises too) become one render. Do not rely on reading state immediately after setState.

20 Stale closures and useEffect races

A function closed over count from render 1 still sees 1. Fix: functional updates, include deps, or a ref of the latest value. Race: effect starts fetch A, then deps change, fetch B starts, A returns later and writes. Fix: AbortController or let cancelled = false in cleanup.

21 forwardRef and useImperativeHandle

forwardRef lets a parent pass a ref to a child function component (usually a DOM node). useImperativeHandle(ref, () => ({ focus })) exposes a small imperative API instead of the raw node. Prefer declarative props; use this for focus, scroll, play. React 19 can pass ref as a prop — still know forwardRef.

TypeScript

01 Interface vs type

Both describe shapes. interface can merge declarations and is typically for object contracts. type can do unions, intersections, mapped/conditional types, tuples. In apps, either is fine for props; use type when you need unions. Do not fight the team style.

02 Generics

Type parameters: function identity<T>(x: T): T. Constraints: T extends { id: string }. Used in useState<User>, API helpers, Promise<T>. Infer when you can; specify when inference fails.

03 Union and intersection

Union A | B: value is one of them; narrow with typeof, in, discriminants. Intersection A & B: must satisfy both. Discriminated unions (kind: "ok" | "err") are the interview gold standard for safe state.

04 Utility types

Partial<T> optional keys. Pick<T, K> subset. Omit<T, K> without keys. Record<K, V> map. Also Required, Readonly, ReturnType, Parameters.

05 Enums vs const assertion

Numeric enums are runtime objects and can be reverse-mapped — often surprising. Prefer as const objects + union of values: const Role = { Admin: "admin" } as const; type Role = typeof Role[keyof typeof Role]. String enums are clearer than numeric if you must use enums.

06 Typing React props and events 
type ButtonProps = {
  label: string;
  onClick: (e: React.MouseEvent<HTMLButtonElement>) => void;
  children?: React.ReactNode;
};
function Button({ label, onClick, children }: ButtonProps) { ... }

Use ComponentProps<"button"> to extend native attrs. Form events: ChangeEvent<HTMLInputElement>.

Redux Toolkit

01 createSlice, reducers, actions

createSlice names a slice, initial state, and reducer map. It generates action creators and action types. You “mutate” state in reducers — Immer turns that into immutable updates. Do not mutate outside the reducer. Put request status in RTK Query or thunks, not giant slices, when it is server cache.

02 configureStore

Combines reducers, adds thunk, DevTools, and serializable/immutability checks in dev. Register slice reducers and API middleware for RTK Query.

03 useSelector / useDispatch

useSelector subscribes; return a small selected value or the component re-renders too often. Use memoized selectors (reselect / createSelector) for derived data. useDispatch returns the store dispatch. Type them with TypedUseSelectorHook and AppDispatch.

04 Immer — when not to use

Inside slice reducers and createReducer, Immer is on. Do not return a new state and also mutate the draft. Do not use Immer for class instances, or freeze/produce across promise boundaries casually. Outside Redux, mutating a draft you then pass to React will confuse you — either mutate a draft in produce or spread copies.

RTK Query

01 createApi, endpoints

createApi defines a reducer path, base query (fetchBaseQuery), and endpoints. query is GET-like cache reads. mutation writes. Hooks: useGetXQuery, useUpdateXMutation.

02 Tags, invalidation, caching

Queries provide tags (providesTags). Mutations invalidateTags so stale queries refetch. Cache key is endpoint + serialized args. Unused data is garbage-collected after keepUnusedDataFor. This is the reason to use RTK Query over hand-rolled useEffect fetch.

03 Optimistic updates, skip, transformResponse

Optimistic: onQueryStarted + updateQueryData, then undo on error. skip / skipToken avoids firing until you have an id/token. transformResponse shapes the payload before it hits the cache. Prefer transform at the API boundary so UI stays dumb.

GraphQL

01 Queries, mutations, variables, fragments

Query reads; mutation writes (and can return new fields). Variables are typed arguments ($id: ID!). Fragments reuse field sets. One endpoint, client asks for a shape. Over-fetching is a REST problem GQL aims to fix; under-fetching N+1 is a server problem (dataloaders).

02 Errors, REST tradeoff, Apollo / RTK

HTTP 200 with errors array is common — check both network and GraphQL errors. REST: simple cache/HTTP semantics, multiple URLs. GQL: flexible payload, harder HTTP cache, needs schema discipline. Apollo Client: normalized cache, hooks. RTK Query: graphqlRequestBaseQuery or custom baseQuery — same tags/cache model you already know.

Browser internals

01 Critical rendering path, DOM, CSSOM, layout, paint, composite

HTML → DOM. CSS → CSSOM. Combined into the render tree. Layout (reflow): geometry. Paint: pixels into layers. Composite: GPU puts layers on screen. Changing geometry is expensive; transform/opacity can often stay on the compositor. Critical path: bytes to first paint — reduce blocking JS/CSS, minify, prioritize above-the-fold.

02 CORS and storage

Cross-origin XHR/fetch is blocked from reading the response unless the server sends ACAO headers. Simple vs preflight (OPTIONS). Credentials need Access-Control-Allow-Credentials and a specific origin, not *. Storage: cookies (with attributes), local/sessionStorage, IndexedDB, Cache Storage for SW.

Webpack

01 Entry, output, loaders, plugins

Entry starts the graph. Output is the emitted files. Loaders transform files (ts-loader, css-loader) as they are imported. Plugins hook the whole compile (HtmlWebpackPlugin, DefinePlugin). Vite is often used now, but interviews still ask this model — Rollup/esbuild use the same ideas.

02 SplitChunks, runtime, contenthash, tree shaking, prod, caching

SplitChunks extracts shared vendor code. Runtime chunk keeps webpack boilerplate separate so contenthash of vendors stays stable. [contenthash] in filenames + long cache headers. Tree shaking (usedExports / sideEffects: false) drops unused ESM. Production mode minifies and sets NODE_ENV. Cache: filesystem cache in webpack 5; browser cache via hashed names.

Performance

01 Code splitting, tree shaking, images, virtualization, memo, bundle analysis

Split routes and heavy widgets with lazy / dynamic import(). Tree-shake ESM. Images: right size, modern formats, lazy load, CDN. Virtualize long lists (react-window) so you do not mount 10k nodes. Memoize only hot paths. Analyze with source-map-explorer or webpack-bundle-analyzer. Also: debounce input, avoid layout thrash, startTransition for non-urgent UI.

Frontend system design

01 Folder structure, auth, cache, errors, API layer, optimistic UI, state
  • Folders: by feature (auth/, cart/) with ui + api + model colocated, plus shared/.
  • Auth: login → tokens (memory + httpOnly cookie preferred) → attach to API → refresh → logout clears cache.
  • Cache: server state in RTK Query/React Query; UI state in Redux/context/local.
  • Errors: normalize at the API layer; toast + boundary + field errors.
  • API layer: one client (base URL, auth, unwrap). UI never raw-fetches.
  • Optimistic UI: update cache first, rollback on fail.
  • State: URL for shareable filters, server cache for remote, local for widgets.

Must-know coding

01 GroupBy, Promise.all, LRU 
function groupBy(arr, key) {
  return arr.reduce((m, x) => {
    (m[x[key]] ??= []).push(x);
    return m;
  }, {});
}

async function all(promises) {
  const out = [];
  for (const p of promises) out.push(await p); // or collect then Promise.all
  return Promise.all(promises);
}

class LRU {
  constructor(limit) { this.limit = limit; this.map = new Map(); }
  get(k) {
    if (!this.map.has(k)) return undefined;
    const v = this.map.get(k);
    this.map.delete(k); this.map.set(k, v);
    return v;
  }
  set(k, v) {
    if (this.map.has(k)) this.map.delete(k);
    this.map.set(k, v);
    if (this.map.size > this.limit) this.map.delete(this.map.keys().next().value);
  }
}

React Native

01 JS thread, UI thread, Bridge vs JSI

JS thread runs React and business logic. UI (main) thread lays out native views. The old Bridge serialized JSON async between them — a bottleneck. JSI is a C++ interface: JS can hold references to native objects and call them more directly (sync possible). New Architecture uses JSI.

02 Hermes, Turbo Modules, Fabric

Hermes is RN’s JS engine: fast startup, bytecode. Turbo Modules lazy-load native modules via JSI. Fabric is the new renderer: concurrent-ready, C++ shadow tree, aligns with React 18. Native Modules are the JS-callable platform APIs (camera, etc.).

03 Deep linking, lifecycle, navigation

Deep links: URL/scheme/universal links map to a screen (React Navigation linking config). Lifecycle: app foreground/background (AppState), not the same as web unload. Navigation: native stack vs JS stack; screens stay mounted depending on navigator; know useFocusEffect.

04 Performance, FlatList, memory

Avoid passing new inline objects to list items; memo rows; getItemLayout if fixed height; windowSize / initialNumToRender / removeClippedSubviews. Images: size and cache. Reanimated worklets for 60fps gestures on the UI thread. Memory: unmount heavy screens, cap caches, profile with Flipper.

05 Offline, push, OTA, permissions

Offline: persist (MMKV / AsyncStorage / SQLite), queue mutations, show cached RTK/React Query data. Push: OS permission, device token, FCM/APNs, handle notification open. OTA (EAS Update / CodePush): JS bundle updates without store review; native changes still need a binary. Permissions: request in context, handle denied/blocked, iOS plist + Android manifest.
